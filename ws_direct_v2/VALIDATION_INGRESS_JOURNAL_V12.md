## 实际链路

asyncio 接收 → 依据内存模板作保守比价 → 机会/状态变化进入 owner →
统一排名、容量及精确身份预留 → 编码增量 → 有序日志真实 fsync →
正回执 → 固定网络 worker → 预热 broker → socket 发送。

没有逐条创建线程或 Task。接收侧按限价上方 2.1% 保守分类，真正的
1.85%/1.65% 分档、0.30/0.22 个百分点替换仍由 owner 执行。
未知模板、无效报价、已有候选/挂单/持仓/signal 目标，以及同币已经排队或处理中的
所有更新均保留；同币 tick/bid0 共用顺序，急跌后的反弹不被最后价格覆盖。
仅能证明无交易动作的无关远价，在接收侧完成比较并更新行情镜像。

队列锁统一保护模板发布、关注币、同币排队/处理状态及接收侧分类。
模板或关注状态改变后重新评估先前完成的远价，队列满时保留有界的待重评记录。
重评未变买一时使用最新有效时间；断线代次、0.5s 时效、发送前最新报价复核均保留。
新增“接收侧远价完成”计数，与过载丢弃分开。原有 8192 容量和显式过载保护仍在。

## 保存及恢复

普通字典仍由 owner 修改；比对已提交的独立 JSON 树，仅编码发生变化的分支。
原有外部字典/列表别名的就地修改也能被观察，不要求交易代码改用特殊容器。
未变分支仍要作相等比较，本次没有保证比对成本与历史记录总量完全无关。
增量字符串是不可变的；writer 解码后按路径复制，后台检查点不会读取可变 owner 对象。

每帧包含 epoch、连续序号、长度及 SHA-256。有序追加的待写事务不会被后来的增量覆盖；
已经到达的多个事务可共用一次同步，不等待新的事务凑批。回执仅在真实 fsync 后签发，
并保留对应精确身份集合。写入失败停止该 writer，后续任务只能得到失败回执，须排查并重启。
不在可能只写了一半的尾部继续追加，不取消落盘后再发送的约束。

完整检查点每累计 256 个事务在独立线程生成；约 4MiB 轮换一个日志段。
新段的完整文件头先持久化再发布；成功检查点覆盖的封闭旧段才允许清理。
Linux 上还同步相应目录。检查点失败保留日志并报告错误，保留日志上限 128MiB，
达到上限停止新提交，防止检查点长期失败时无限占盘。
普通追加只通知日志线程；检查点使用独立 Event，避免每笔订单额外唤醒检查点线程。

恢复从当前 epoch 的校验检查点按序重放；只允许忽略最后一个活动段的未完成尾帧。
完整帧校验错误、缺检查点或序号缺口会停止恢复，不能回退到入口 JSON 的旧 seed。
支持读旧独立 JSON/双槽账本，再在启动阶段转换为新日志。正常退出导出独立完整 JSON。
入口使用 bundle version 2，旧读取器会停止，不会把 seed 当当前状态；正常导出恢复 version 1。
维护读取及离线迁移共用解析器；手动同步备份包含所有日志和检查点。
运行中备份应复制整个 state 目录，不能仅备份两个 JSON。

普通撤单仍单独排队、串行执行，前笔返回后间隔 1.5s；新发单不等待该队列。
普通 8 单、满 3 仓及末根 bar 例外、额外 2 个补挂单和 6 仓停补规则均保留。

## 压力条件与口径

800 币，2 个逻辑 CPU 亲和性，19 个固定网络 worker，1000 笔历史意图、
5000 笔历史计时、真实临时文件与 fsync、真实 broker 循环/签名/编码到假 socket。
含 130 个 1.7% 距离背景币、已有挂单替换和按真实 1.5s 节奏执行的假撤单回包。
平均 5/32 为 tick，27/32 为未变买一。没有 TLS、公网 RTT、真实账户 SQLite 及实盘终端负载；
CPU 亲和性不等同于云机 CPU 配额。正式持仓/平仓、换 bar 与账户变化由回归覆盖，
本轮吞吐数据不构成这些负载组合的延迟上界。

计时从原始本机收到报价到实际 socket 发送，保留保存及线程调度等待。
“所有订单”也保留背景订单的依据报价年龄；容量/替换条件较晚成立的旧报价不删除。
不同阶段的分位数不能相加；保存阶段还包含调度与编码，不能全称为磁盘延迟。
退出码 2 表示完整性通过但 10ms 失败，不能解释为性能达标。
