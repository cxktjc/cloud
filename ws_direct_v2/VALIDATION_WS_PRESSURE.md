# 双路行情积压与重连修复（2026-11-20）

## 原因与改动

- bookTicker 的卖盘/正买量变化也携带同一个 bid0，以前全部触发 owner，重复运行整套准入/换单。
  未进入排名且远于 2.1% 的报价也运行全量选择，挤占有效跨线与定时维护的处理时间。
- 只去掉连续同价/同有效性的 book 重复输入，保持接收时间与买量新鲜；所有价格/有效性变化按序处理。
  未跟踪且未入排名的远价走快速路径；模板更新、在途结果、旧挂单和 signal 目标不走该快捷判断。
- 以前 queue.Full 冒泡到 consumer，导致主动退出 WS 并重连；现在就地作废受影响分组旧代次，
  继续读取 socket，显式统计过载丢弃，队列排至低水位后等 fresh owner 事件恢复。溢出期间不交易遗漏的旧行情。
- Python 3.11+ 省去每帧额外 recv Task，每 64 帧主动调度其他连接/心跳；3.10 使用原 wait_for 兼容。
- 以前首条 DATA READY 就重置重试间隔，连续几秒断线会一直 1 秒重试；现在有效连接存续 30 秒后才重置，
  短连接按 1/2/4/8/16/30 秒退避。连接日志增加存续时间和接收/有效报文数。
- 未扩大队列、放宽 0.5 秒积压限制，未修改策略价格、挂单数量、替换优势、补挂或 1.5 秒撤单间隔。

## 离线负载复现

工具：`tests/benchmark_ws_pressure.py`。800 币对、8 普通挂单、tick/book 混合输入，同时执行真实 owner、
临时账本维护与独立价格镜像线程；交易所适配器为模拟，未连接生产账户或发单。
报文模式约 80% book / 20% tick，含同价买量更新，不能代表所有报文都是变价的极端行情。

6317 个事件全部完成决策，无过载丢弃；仍为 8 个模拟委托，没有额外重复下单。
该轮与全量回归同时运行，结果不是专用服务器吞吐上限。
修改前使用 git archive 导出的隔离旧源码与同一负载工具，路径为忽略目录
`var/validation_v2/baseline_3557ac9/ws_direct_v2/baseline_load.json`；未改旧源码或生产文件。

远价单事件 cProfile 同机 300 次：均值约 4.179ms → 0.241ms，P95 4.634ms → 0.278ms。
这是指定模拟场景的处理耗时，不代表真实下单延迟。

## 实盘验证边界

以上为内存接入负载、错误注入和临时文件验证，不含 cloud 的真实 WS/TLS 链路。
本地队列/重连缺陷已修复；外部 TCP 连接是否稳定，需要 cloud 拉取并重启后观察。
如仍出现 ConnectionClosedError，新日志可区分实际连接存续时间、收包量和本地积压，不能只凭错误字符串判定原因。
