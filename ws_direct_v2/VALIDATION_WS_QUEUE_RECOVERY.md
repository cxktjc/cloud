# v2 持续行情积压复查与修复（2026-11-20）

用户在更新 `83c3520` 后报告：接收 4,724/s，决策 691/s，当前积压 133，历史峰值 8,192，累计过载丢弃 25,933。多个 tick/depth 分组同时 overflow，说明共享 owner 队列确实曾满载；“已恢复”和当前队列下降不代表处理吞吐已足够。未访问服务器，以下为本地代码复查和可重复的离线证据。

## 根因与改动

上轮快路径只针对均匀价格下的空簿/满 8 单做充分验证，漏掉以下状态：

1. 堆顶包含已挂出、已持有、signal 目标等无法作为普通新单的币对。某个已挂单价差很低时，快路径误以为存在足够好的新候选，几乎每个其他币的变价都重复完整计划；真实完整计划又正确排除该已挂币，最终没有动作。
2. 有 1～7 个普通挂单时，快路径未覆盖，未达到下一档/替换优势的报价仍逐条进入完整筛选。
3. 满 3 仓且未进入退出前最后一根 bar 时，普通新挂本来被禁止，却仍重复计算普通入场计划。
4. 替换发送被拒、价格已反弹后，持久化 pending_rotation 也可能让全局快路径失效。

本次用真实未持有/未挂出/非 signal 目标的候选做保守界限检查。已挂币的排名只暂时取出后放回，不抹掉行情或排名。检查覆盖 0～8 个有效普通挂单，并分别检查正常准入档位、替换优势、现有订单距离/有效期/资金档、满仓及到期前末根 bar 例外。等待中的替换保留发起时门槛，身份不匹配、成交、过期及未知占位仍进入完整状态处理。

文件变化、网络结果、已有订单/持仓/目标的行情，以及可能产生新挂/替换的跨线均继续进入完整路径。满仓后已有普通单仍先走完整撤单计划，再跳过无动作的普通新候选；补挂不受该普通仓位快路径阻挡。周期维护仍执行成交、平仓、撤单重试和时间状态转换。

没有增加 8,192 队列容量，没有延长 0.5s 积压预算，没有合并变化行情或隐藏 overflow 日志。信号、QV、资金比例、挂单价差、满 8 单先发替换、补挂、1.5s 撤单间隔及平仓逻辑不变。

## 同条件复现

基线为 `83c3520` 的 `ws_direct.py`，在独立离线 Python 进程装载其源码，使用本次同一压力工具。只替换内存中的基线类，不回写工作区或生产账本。

条件：800 币，20% tick / 80% bid0，所有输入每次访问均变价，不利用未变买一去重；真实临时账本/fsync、镜像线程，模拟交易所。固定 fixture bar 时钟；每次运行 3s，逐项顺序执行，未与测试或 profiler 同时运行。工具先消费全部初始行情和 ACK 唤醒，再捕获起始计数，防止初始化事件计入测量。

- `owned_spread`：8 个普通单，其中一个现有订单价差 -1%，其余及新候选约 +1%，新候选没有替换优势。
- `partial_book`：3 个普通单约 +1%，其他候选约 +2%，没有达到空位准入或替换优势。
