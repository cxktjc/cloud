# 普通单重复入场和补挂频繁撤单修复（2026-11-20）

## 普通单身份隔离

普通 entry 不再将币对/bar 的确定性 ID 直接作为物理下单 ID。
每个新物理尝试先保存 `entry_submission_sequence`，再注册精确身份及 tracked 占位，最后才允许网络发送。
使用与旧版不同的哈希命名域和 80-bit 后缀，clientOrderId 长度 33，不超过交易所 36 字符限制。
同 bar 撤单重挂、精确确认不存在后重试及重启都使用不同身份；尚未确认的原单继续占位，不重新发送。

换出不补回、确定拒单抑制按完整信号计划保留，不随物理 ID 改变；
确认不存在后的重试次数按币对/bar 汇总，换新 ID 不会重置上限。
已有账本和订单继续沿用原身份，资金、仓位及累计成交不重建。

账户流、查询缓存和 broker 查询返回校验 symbol/clientOrderId/orderId；
已知 orderId 与回报矛盾时保留本地身份，不能被旧 orderId 覆盖。
撤单和下单 ACK 回调也执行身份核对。旧版未获 ACK 的入场记录，早于本次发送的旧回报不作为终态。

## 补挂单固定数量

首次新补挂仍按当时的 trade 实际仓数选择 50/30/20，并执行最低金额/精度规则。
已发出的补挂不参加普通 sizing 调整，持仓数、资金改变或重启不会改变其原价格、数量或订单身份。
补挂发送闸门不再要求旧资金权重等于当前仓数对应权重，防止已排队补挂因其他仓位变化而被拒绝。

保留 signal 结束、trade 达到 6 仓、部分成交后撤余单、额外 2 单容量及强平/手动平仓保护。
普通 8 单计数、0.30/0.22 个百分点替换、2.1% 距离撤单和回包后 1.5 秒撤单间隔保持原规则。
本修复不自动撤销或收编已经丢失归属的生产订单。
